# UI Design Prompt

以下內容可直接複製到 Claude Design 使用。此 prompt 只描述功能與資訊架構，不包含視覺風格、色彩、字體或元件規範（由 Claude Design 既有的 design system 決定）。

對應架構：[docs/spec](spec/README.md) 2026-09-25 修訂（Privacy Agent + Operator）；Agent 關係與流程圖見 [DESIGN.md](DESIGN.md)。

---

請為一個**以隱私為核心的桌面端 AI Agent 平台（Electron 應用）**設計 UI。

這個平台讓一般使用者放心地請 AI 代理做任何事，包括瀏覽網頁、操作桌面 App、處理檔案與資料。使用者不需要知道哪些內容可以交給雲端 AI，平台會替他判斷。

平台有三種 Agent：

- **Privacy Agent（隱私代理）**
  - 所有任務的唯一入口，執行在使用者自己的電腦（本地小模型）或自架伺服器（自架大模型）上。
  - 它先檢查任務裡有哪些敏感資料（人名、電話、證件、病歷、財務、公司機密⋯），再決定怎麼處理：
    - 以替代名稱（例如 `⟦PERSON_1⟧`）取代真值後交給雲端；
    - 只交出資料的結構，由雲端寫處理程式、在本機跑；
    - 完全在本機處理；
    - 先問使用者。
- **Planner（規劃者）**：只在「SLM 模式」存在的雲端 Agent。負責把去敏後的任務拆解、派給 Operator，它只看得到替代名稱。
- **Operator（執行者）**
  - 多個，各自由一個「Persona」設定定義人設、工具、內嵌瀏覽器、工作目錄，通常使用雲端模型，可在背景持續執行。
  - 送往雲端的內容都會自動去敏；Operator 需要真值去填表或寄信時，平台在本機替它還原。

Privacy Agent 有兩種模式，由使用者在設定中選擇：

- **SLM 模式**：本地小模型只做固定的隱私判斷，任務規劃交給雲端 Planner。
- **LLM 模式**：自架大模型直接擔任規劃者，沒有 Planner。

應用有兩種視窗：**主視窗（Main Window）**一個，**Operator 視窗（Operator Window）**每個 Operator 各一個，可獨立開關與並排。請設計以下畫面與流程。

## 1. 主視窗（Main Window）

主視窗是全域控制台，也是與 Privacy Agent 對話的地方，包含以下區域：

### 1.1 隱私狀態列（常駐頂部或側欄頂部）
- 顯示目前的 Privacy 模式（SLM／LLM）、隱私等級（嚴格／平衡／寬鬆）、Privacy Agent 使用的模型與位置（本機／區網／雲端）。
- Privacy Agent 的模型無法連線時顯示醒目警示，說明「送往雲端的任務已暫停」，並提供前往設定的入口。
- 使用者把 Privacy Agent 設為雲端模型時，以警告樣式常駐提示「隱私代理使用雲端模型，原始資料會送達該服務」。
- 沙箱不可用、改用相容模式時，顯示次要提示。

### 1.2 Agent 側欄（Agent List）
- 最上方固定 **Privacy Agent**；SLM 模式下，其下方固定 **Planner**（僅供檢視，不能直接對話）。
- 下方列出所有 Operator，每項顯示：
  - 名稱、頭像或代號；
  - 狀態（idle / working / waiting for input / error / offline）；
  - 正在執行的任務標題、排隊任務數；
  - 瀏覽器或桌面畫面縮圖（有活動時才顯示）；
  - 行程資源用量（記憶體、CPU，可折疊）；
  - 模型位置標記：☁ 雲端 或 本機。
- 狀態為 waiting for input 時顯示醒目徽章；隱私確認類的徽章要與一般確認區分。
- 點擊 Operator 開啟或聚焦其獨立視窗；點擊 Planner 在主視窗顯示其唯讀 Thread。
- 底部有「新增 Operator」入口；支援依狀態篩選與搜尋。

### 1.3 Privacy Agent 對話面板（Privacy Chat）
- 主視窗中央是與 Privacy Agent 的對話，使用者在這裡下達所有任務。可開多條對話（Thread）。
- 訊息類型：
  - 使用者訊息、Privacy Agent 回覆（替代名稱已還原為真值）；
  - **思維鏈**（可展開／收合）；
  - **工具呼叫紀錄**；
  - **委派卡片**：目標 Operator 或 Planner、任務摘要、同步／非同步、即時狀態、結果摘要，可點擊跳到對應 Thread；
  - **系統事件**。
- **隱私卡片**：每個任務附一張可展開的卡片，這是本產品最重要的元件，要讓非技術使用者一眼看懂：
  - 採用的處理方式，以白話呈現，例如「只在本機處理」「替換 5 個敏感資料後交給雲端」「只給雲端資料結構，在本機計算」「需要你確認」。
  - 資料送往哪個服務（Provider 名稱、雲端／本機）。
  - 各類敏感資料的處理數量（例如 人名 ×3 已替換、信用卡 ×1 已封鎖）。
  - 「原文 ↔ 實際送出內容」對照檢視：替代名稱以色塊標示，滑過顯示真值；被封鎖的內容以另一種樣式標示。
  - 若有本機執行的腳本，可展開檢視腳本內容與執行結果摘要。
  - 連結到 Privacy Ledger 的完整紀錄。
- 輸入區：
  - 文字、附件；
  - 語音輸入：push-to-talk 與自動分段、上傳音訊檔。若語音服務在雲端且隱私等級要求，第一次使用時先顯示說明與同意；「嚴格」等級下隱藏雲端語音。
  - 附加檔案時，就地提示該檔案預計的處理方式，例如試算表會顯示「只給雲端資料結構」。
- 支援「傳送」與「派發為背景任務」兩種送出方式。
- 串流狀態：正在檢查敏感資料、正在思考、正在本機執行腳本、等待 Operator、等待你確認。

### 1.4 任務樹（Task Tree）
- 以樹狀顯示任務：根節點是使用者對 Privacy Agent 的任務；SLM 模式下第二層是 Planner；再下層是各 Operator 的子任務。每個節點顯示狀態、Agent、開始時間、耗時、結果摘要與處理方式圖示。
- 節點可展開查看訊息與工具呼叫，或跳轉到 Operator 視窗的對應 Thread。
- 可取消進行中的子任務（需二次確認）。

### 1.5 Action Center（通知與待辦中心）
- 全域通知清單，每則有嚴重度（info / success / warning / error / action required）、來源 Agent、標題、內容、時間、已讀狀態。
- **action required** 類型置頂直到處理，共六種人工確認：
  1. **question**：Operator 提問，需要文字回答（可能附選項）。
  2. **tool approval**：Operator 想執行工具（工具名稱、參數、風險等級、理由），可「允許」「拒絕」「允許並修改參數」。
  3. **auth required**：Operator 在某網站遇到登入或 MFA，使用者到該 Operator 視窗的瀏覽器完成後按「繼續」。
  4. **captcha**：同上，附截圖預覽。
  5. **tool error**：工具失敗的結構化回報，可「重試」或「忽略」。
  6. **隱私確認（privacy confirm）**：有四種原因，每種都要用白話說明：
     - 含高敏感資料，例如證件、病歷、帳號；
     - 系統無法判斷；
     - 隱私代理模型離線；
     - 要把真實資料送到任務中沒出現過的網站。

     卡片顯示「即將送出的內容（已替換）」與目的地。按鈕依情況出現：「允許送出」「改為只在本機處理」「本次只用基本規則檢查後送出」（僅模型離線時）、「取消」。
- 通知可直接在 Action Center 內回應，也可跳轉到對應視窗。
- 有「全部標為已讀」與依嚴重度、來源篩選。
- 系統層級也會發桌面 Toast，請設計 Toast 的簡短版型（隱私確認的 Toast 不顯示敏感內容，只顯示類別與「請確認」）。

### 1.6 Privacy Ledger（隱私紀錄）
- 可切換的面板，時間軸列出每一次「資料離開這台電腦」的紀錄：時間、任務、Agent、目的服務、處理方式、各類別數量、使用者授權事件（例如允許新網站、只用基本規則）。
- 可依任務、服務、類別、日期篩選；點擊展開「原文 ↔ 送出內容」對照。
- 可匯出。
- 空狀態要能傳達「目前沒有任何資料送出」的安心感。

## 2. Operator 視窗（Operator Window）

每個 Operator 一個獨立視窗，關閉只是隱藏，Operator 在背景繼續執行。視窗分三區：

### 2.1 Thread 列表（左側）
- 列出此 Operator 的 Thread，每條有來源標籤：**user**（使用者直接介入，固定置頂）、**privacy**（Privacy Agent 派發）、**planner**（Planner 派發）、**schedule**、**event**、**webhook**。
- 每條顯示標題、最後活動時間、狀態（queued / running / waiting for input / done / failed）。
- 依最近活動排序，可搜尋。

### 2.2 對話面板（中央）
- 顯示選中 Thread 的完整歷程，訊息類型與主視窗相同，另加：
  - **瀏覽器動作紀錄**（導航、點擊、擷取，附小截圖）；
  - Phase 2 的**桌面動作紀錄**（開啟 App、點擊、輸入，附小截圖）。
- 訊息在本機以真值顯示，但被替換過的值以色塊標示，滑過顯示「雲端看到的是 ⟦PERSON_1⟧」，讓使用者理解雲端實際看到什麼。
- Operator 使用雲端模型時，頂部顯示提示「此對話的內容會在替換敏感資料後送往雲端」。
- 使用者可在任一 Thread 打字介入；Operator 正在執行時，介入訊息標示「將於下一輪處理」。
- 輸入區：文字、附件、語音。
- 頂部工具列：Operator 名稱與狀態、綁定的模型與位置標記、「暫停 / 繼續」、「取消目前任務」、「開啟設定」。
- Thread 處於 waiting for input 時，在對話底部以嵌入式卡片呈現待處理的確認（同 Action Center 的六種類型）。

### 2.3 瀏覽器區（右側）
- 內嵌瀏覽器畫面，頂部是分頁列與網址列，網址列可手動導航，有前進、後退、重新整理。
- 顯示「Agent 正在操作中」的狀態，以及 Agent 目前聚焦元素的非侵入式高亮。
- 使用者可隨時接管（登入、解驗證碼），接管時顯示「使用者操作中，Agent 暫停」與「交還給 Agent」按鈕。
- 可拖動調整寬度、全螢幕、摺疊。
- 可切換檢視「雲端看到的截圖」：敏感區塊塗黑並標註替代名稱。

### 2.4 執行日誌（底部，可摺疊）
- 時間軸形式的 trace：每個 Run 的 span（模型呼叫、工具呼叫、MCP、瀏覽器動作、隱私檢查、本機腳本執行），顯示耗時與 token 用量。
- 可依 Run 篩選、可匯出。

## 3. Operator 設定（Operator Settings）

從 Operator 視窗或主視窗進入，以分頁或分段呈現：

- **基本**：名稱、描述（Privacy Agent 或 Planner 派發時的依據，請提示使用者寫清楚專長）、頭像或代號、人設 system prompt。
- **模型**：使用全域預設，或指定 Provider 與模型、溫度等參數；顯示所選 Provider 的位置（本機／區網／雲端），選雲端時說明「送出前會自動去敏」。
- **Skills**：列出已載入的 skill（名稱、描述、來源、是否含可執行程式碼），可啟用／停用、開啟資料夾；首次載入含程式碼的非內建 skill 需一次性信任確認。
- **MCP 伺服器**：列出此 Operator 的 MCP 伺服器，顯示連線狀態與工具數，可新增（stdio 或 HTTP）、編輯、移除、重新連線。
- **工具與風險等級**：
  - 表格列出所有工具（內建、MCP、skill），每個工具可設定風險等級：**low**（自動執行）、**medium**（派發者可代為批准）、**high**（必須由使用者批准），未設定預設 medium。
  - 另一欄「外送參數」：標記哪些參數會把資料送到外部網站；這些參數還原真值後若要送往新網站，會先請使用者確認。
  - 提供依來源分組與批次調整。
- **瀏覽器**：啟用／停用、清除瀏覽資料、檢視目前登入的網站，並提示「在雲端 Operator 長期登入高敏感網站（例如信箱、網銀）有風險」。
- **桌面操作（Phase 2）**：啟用／停用、允許操作的 App 白名單（新增時從已安裝 App 挑選）、系統權限狀態（輔助使用、螢幕錄製）與授權引導；說明「白名單以外的視窗在截圖中一律塗黑」。
- **執行**：最大並行數（預設 1，大於 1 時警告「多個任務會共用同一個瀏覽器登入狀態」）、同步任務逾時。
- **觸發器**：訂閱的內部事件與 prompt 模板；此 Operator 的 webhook 網址與 token。說明觸發的內容會先經過 Privacy Agent。
- **危險區**：停用、刪除（含是否一併刪除工作目錄與瀏覽資料）。

## 4. 全域設定（Global Settings）

- **隱私（Privacy）**（最重要的設定頁，要讓非技術使用者看得懂）：
  - **Privacy Agent 模型**：選擇 Provider 與模型，顯示位置（本機／區網／雲端）與連線狀態。選雲端時顯示需確認的警告對話框。
  - **模式**：SLM 模式／LLM 模式，並以白話說明差異與建議的模型規模（例如「筆電上的小模型 → SLM 模式；公司自架的大模型 → LLM 模式」）。切換時提示「進行中的任務會以原模式完成」。
  - **隱私等級**：嚴格／平衡（預設）／寬鬆，以卡片呈現各等級的效果與取捨。
  - **類別設定**（進階，可展開）：列出敏感類別（憑證密碼、證件、金融帳號、健康、人名、聯絡方式、位置、公司機密、資料檔、公開內容），每類可選「直接送出／替換後送出／替換並先問我／只給資料結構／封鎖」。「憑證密碼」固定為封鎖，不可修改，需說明原因。
  - **自訂詞彙**：新增公司名、專案代號等，指定類別。
  - **本機運算**：沙箱狀態（使用中的隔離方式、是否為相容模式與補裝說明）、Python 執行環境安裝狀態與下載進度、執行時間與記憶體上限、回給雲端的結果列數上限。
  - **紀錄保留**：Ledger 保留天數、匯出。
- **Model Providers**：
  - Provider 清單：名稱、類型（OpenAI / OpenAI 相容 / Azure OpenAI）、Base URL、API Key（只顯示尾碼四碼）、**位置**（本機／區網／雲端，由網址自動判斷；可把公司自架的公網端點標為「私有」，需確認）、支援能力（即時語音、語音轉文字、結構化輸出）。
  - 新增／編輯表單依類型顯示不同欄位，有「測試連線」。
  - 「偵測本機模型」按鈕：掃描 Ollama、LM Studio 等常見本機服務並列出可用模型。
  - 可設定全域預設模型（Operator 用）。
- **Planner**：Planner 的模型綁定與 system prompt（僅 SLM 模式顯示為啟用）。
- **語音**：語音服務 Provider 與位置；雲端語音在各隱私等級下的行為說明。
- **MCP 範本**：全域可重複使用的 MCP 伺服器定義，供各 Operator 引用。
- **排程（Schedules）**：
  - 排程清單：名稱、cron 表達式與人類可讀翻譯、時區、目標 Operator（可選「交給 Privacy Agent 決定」）、啟用狀態、上次與下次執行。
  - 新增／編輯表單含 prompt 模板編輯器，支援 `{{current_time}}`、`{{date}}`、`{{timestamp}}` 等變數，提供插入器與預覽。
  - 可「立即執行」、查看執行歷史（含 App 未開啟而略過的紀錄）。
- **通知**：
  - 桌面 Toast 開關與嚴重度門檻。
  - **外部轉發規則**：條件（嚴重度／來源／類型）→ 目標 webhook URL、header、body 模板，內建 ntfy 與 Telegram 範本，可「發送測試通知」。
  - 說明「轉發到外部的內容會自動封鎖敏感資料」，預覽時顯示封鎖後的樣子。
- **進階**：
  - Trace 匯出到 OTLP endpoint；endpoint 在雲端時說明「只會送出時間與統計，不含內容」。
  - 資料保留天數、本機 CDP port 與 webhook port 顯示、資料庫位置。
  - 應用更新：檢查更新、目前版本、更新完成後提示重啟。

## 5. 首次啟動與建立 Operator 流程

- **首次啟動精靈**：
  1. **介紹**：一句話說明「你的資料會先由你電腦上的隱私代理檢查，敏感內容不會原樣交給雲端」。
  2. **設定隱私代理模型**：自動偵測本機模型服務，列出可選模型；找不到時提供安裝 Ollama／LM Studio 的簡短指引，並允許輸入公司自架端點。
  3. **選擇模式**與**隱私等級**：預設 SLM 模式與「平衡」，各附白話說明。
  4. **設定雲端 Provider**：用於 Planner 與 Operator，輸入 API Key、測試連線。可略過，略過時只能純本機處理。
  5. **建立第一個 Operator**：從內建範本挑選，例如網路研究員、資料整理員、程式助手。
  6. 進入主視窗，示範一個含假個資的範例任務，展示隱私卡片如何運作。
- **建立 Operator**：精靈或單頁表單，至少填名稱、描述、人設 prompt，其餘採預設。

## 6. 關鍵狀態與空狀態

請為以下情境設計狀態畫面：
- 尚未設定 Privacy Agent 模型（無法下任務，引導設定）。
- Privacy Agent 模型離線：任務暫停，說明原因與可選動作。
- Privacy Agent 使用雲端模型（常駐警告）。
- 沒有任何 Operator 時的主視窗；沒有雲端 Provider 時，只能純本機處理的狀態。
- Operator 離線或崩潰重啟中（顯示重啟倒數與重試次數）。
- Provider 連線失敗或 API Key 無效。
- 本機腳本執行中（顯示進度、已用時間、可取消），以及腳本失敗、Operator 修正後重試的過程。
- 沙箱改用相容模式。
- Operator 視窗中瀏覽器尚未啟動；使用者接管瀏覽器或桌面中。
- 長時間執行的背景任務（顯示已執行時間與最近一個動作）。
- Privacy Ledger 為空。

## 7. 互動原則（功能層面）

- **讓使用者安心、而不是焦慮**：
  - 隱私資訊預設以白話摘要呈現，細節收在展開區，不要把每次處理都做成警告。
  - 真正需要使用者決定時（隱私確認）才打斷，而且要說清楚「會送出什麼、送去哪裡、不同意會怎樣」。
- **透明可追溯**：任何送出雲端的內容，都能從對話中的隱私卡片或 Ledger 找到「原文 ↔ 送出內容」對照。
- 背景任務不因視窗切換、隱藏或在其他 Operator 視窗操作而中斷；UI 讓使用者隨時知道「現在有多少東西在跑」與「有多少東西在等我」。
- 所有人工確認都能在三個地方處理：Action Center、對話面板內嵌卡片、桌面 Toast 的快速動作（隱私確認的 Toast 只導向 App，不在 Toast 顯示內容）。
- 委派關係可追溯：從 Privacy Agent 的委派卡片或任務樹能跳到 Planner／Operator Thread；從 Operator Thread 能回到發起它的 Privacy Agent 任務。
- 雲端與本機要有一致的視覺語彙，例如雲端標記、替代名稱色塊、封鎖樣式，在所有畫面中用法一致。
- 支援多個 Operator 視窗並排觀察。
- 主視窗與 Operator 視窗都需要適應較窄的寬度（側欄可收合、瀏覽器區可摺疊、隱私卡片可收為單行摘要）。
